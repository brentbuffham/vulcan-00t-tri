## WHAT IS SOLVED (high confidence, GT-verified)
- **File layout:** 60-byte header → COORDS `[8326 .. 79563]` → FACES/connectivity
  `[79563 .. 141230]` (the `e0 03` short-record run) → attributes + PNG thumbnail.
- **Coords = seed + deltas + periodic fulls:**
  - **seed/origin** = first point, full 3 doubles @8326. = EXACT GT vertex (0.001 m).
  - **delta records** nudge ONE coordinate via **SPLICE** = keep prev's high bytes,
    replace low bytes with the record's payload. **The splice is EXACT** (pure byte ops,
    no rounding, cascades without drift).
  - **fulls** re-anchor every few records so deltas can't drift out of byte-range.
- **Values are TRUE WORLD COORDS** — no inversion, no swap, no scale/screen transform
  (ruled out: X-fulls∈GT eastings, Y-fulls∈GT northings, Z-fulls∈GT elevations).
- Surface NN spacing ≈ 4 m (matches Brent's 4.5×5.2 drill pattern).

## KEY FINDINGS THIS SESSION (don't re-derive / don't repeat dead ends)
- **Additive/IDELTA ruled OUT** (62% vs splice's 84% with exact prev). It IS the splice.
- **"Deltas are noise" was a RED HERRING.** They only look like noise because a WRONG
  AXIS assignment corrupts that axis's running prev → everything downstream drifts to
  garbage. With the *correct* axis + exact prev, splice hits **X 8×, Y 5×, Z 2×** the
  coincidental floor. So: VALUE math = solved; the lock = AXIS + ORDER.
- **FIRST clean axis signal = the COUNT byte (delta byte-length):**
  `count=3` (4-byte delta) → **always Z** (1626 records, ZERO X/Y). `count=4`→mostly Z,
  `count=5`→X/Y/Z. Byte-length encodes axis because small-magnitude Z needs fewer bytes
  than big X/Y. The 9-month effort never used this.
- **Coords are in MESH-TRAVERSAL order, NOT point order.** 3 consecutive coords belong to
  3 DIFFERENT vertices. Even with exact values + GT-picked axis, only **0.2%** of vertices
  reconstruct, because a vertex's X/Y/Z are spread across the stream by the mesh walk.
  8+ assembly models tried, all ~0.2%. The order is in the connectivity.
- **Per-page origins: ruled OUT** (geometry is one continuous stream across 2048-byte
  pages; no reset at page boundaries).
- **Coord/face boundary fix:** the first `e0 03` @70664 is a coord-section MARKER followed
  by 8899 more bytes of coords; the real FACE block starts at the dense short-record run
  ≈79563. (Auto-detect: first `e0 03` with 3 within 90 bytes.)
