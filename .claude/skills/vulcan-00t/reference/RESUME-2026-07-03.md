## BREAKTHROUGH 1: UNIFIED TOKEN GRAMMAR (proven, both sections)
Byte stream = sequence of tokens:
- `V-token`: prefix c∈{0x00..0x06} then c+1 payload bytes (the old COUNT+payload).
- `T-token`: byte≥0x20 (not FULL) + 1 arg byte. In coords the arg (old SEP) is
  ALWAYS ≡7 mod 8; its high 5 bits vary = state-machine input. In faces arg低3位
  ∈{3,7} observed.
- `E-token`: 0xE0..0xFF + 2 arg bytes. `e0 03 00`/`e0 03 15` = FACE record
  separators; `e0 03 14` = the W1 coord section marker. Same token, one language.
- `FULL`: raw 8-byte BE double, first byte ∈{40,41,C0,C1} = IEEE-754 exponent byte
  of world coords (X→40 EB, Y→41 03/04, Z→40 84, negatives C0/C1). NOT a special
  marker — just the double itself. Sanity-check value to disambiguate from T-token.
- Escape/solo bytes 0x07..0x1f exist (~610 in intercepts coords) — W3/W11-13 zones,
  still the main framing gap.
Tokenizer: see python/coord_beam2.py / face_* scripts.

## BREAKTHROUGH 2: FACES = SPLICED VERTEX-ID REFS (proven)

  walk (multiple cursors ±1, row strides ~100-160). 99.3% of spliced ids < NV.
- Record↔triangle DP alignment on the GT "newness" sequence lands EXACTLY at

  lexsort, serpentine gap-clustered sort, PCA sorts (all tested ≈ chance).
  π recovery via voting failed (7.2% purity) — V-refs likely name vertices not
  necessarily IN the aligned triangle (gate/cursor semantics still open).
